# Plan Feature Workflow

## Step 1: Understand the Feature

Identify:

* the feature goal,
* user requirements,
* expected behavior,
* acceptance criteria,
* constraints,
* edge cases,
* security implications,
* performance requirements,
* and integration requirements.

Inspect the existing project before making assumptions.

## Step 2: Inspect the Existing System

Review relevant:

* architecture,
* source code,
* components,
* APIs,
* data models,
* dependencies,
* configuration,
* tests,
* documentation,
* and project conventions.

Identify the parts of the system likely to be affected.

## Step 3: Analyze Implementation Options

Identify meaningful implementation approaches.

Compare relevant options based on:

* compatibility,
* complexity,
* maintainability,
* security,
* performance,
* scalability,
* implementation cost,
* regression risk,
* and long-term impact.

Recommend the approach most suitable for the existing project.

## Step 4: Design the Feature

Define:

* affected components,
* responsibilities,
* data flow,
* interfaces,
* APIs,
* data changes,
* validation,
* error handling,
* security boundaries,
* and integration points.

Avoid unnecessary architectural changes.

## Step 5: Assess Impact

Identify:

* files likely to change,
* components affected,
* dependencies,
* potential regressions,
* migration requirements,
* testing requirements,
* security risks,
* and documentation changes.

## Step 6: Create an Implementation Plan

Break the feature into clear implementation steps.

Define the recommended implementation order and verification requirements.

Keep the plan proportional to the feature's complexity.

## Step 7: Present the Recommendation

Before significant implementation, summarize:

* the feature understanding,
* the recommended approach,
* alternatives considered,
* important trade-offs,
* affected areas,
* risks,
* and implementation steps.

Clearly identify assumptions or unresolved decisions.
