# Software Architecture

Use this skill when designing, changing, evaluating, or improving the architecture of a software system or significant feature.

## Understand Requirements

Identify relevant:

* functional requirements,
* non-functional requirements,
* constraints,
* expected scale,
* security needs,
* reliability needs,
* performance requirements,
* maintainability goals,
* and future growth expectations.

## Analyze the System

Identify:

* system boundaries,
* major components,
* responsibilities,
* dependencies,
* interfaces,
* data flow,
* external systems,
* trust boundaries,
* and operational requirements.

## Design the Architecture

Choose an architecture appropriate to the project's actual complexity.

Define:

* component responsibilities,
* communication patterns,
* data ownership,
* interfaces,
* dependency direction,
* failure boundaries,
* security boundaries,
* and scalability strategy where relevant.

Prefer clear and maintainable designs.

Avoid unnecessary distributed systems, microservices, abstraction layers, or complexity when a simpler architecture is sufficient.

## Evaluate Trade-offs

When meaningful alternatives exist, evaluate:

* complexity,
* maintainability,
* scalability,
* performance,
* reliability,
* security,
* development speed,
* operational cost,
* and long-term sustainability.

Recommend the architecture that best fits the project rather than automatically selecting popular patterns.

## Plan Evolution

Consider how the architecture can evolve without premature overengineering.

Identify likely:

* extension points,
* technical risks,
* migration concerns,
* scaling limits,
* and architectural assumptions.

Clearly distinguish current requirements from possible future requirements.
