# Code Review

Use this skill when reviewing code, pull requests, features, modules, or implementation quality.

## Review Correctness

Check whether the implementation:

* satisfies requirements,
* handles expected scenarios,
* handles relevant edge cases,
* and introduces logical errors or regressions.

## Review Code Quality

Evaluate:

* readability,
* naming,
* modularity,
* responsibilities,
* duplication,
* complexity,
* maintainability,
* consistency,
* and project conventions.

## Review Reliability

Inspect:

* error handling,
* failure scenarios,
* assumptions,
* resource handling,
* and integration risks.

## Review Security

When relevant, inspect:

* input validation,
* authentication,
* authorization,
* sensitive data,
* secrets,
* dependency risks,
* configuration,
* and realistic attack surfaces.

## Review Performance

When relevant, identify meaningful:

* algorithmic inefficiencies,
* unnecessary resource usage,
* database problems,
* network inefficiencies,
* memory issues,
* or scalability limitations.

Avoid premature optimization recommendations.

## Provide Feedback

Prioritize findings as:

* critical,
* important,
* improvement,
* or optional.

Explain:

* what the issue is,
* why it matters,
* its likely impact,
* and the recommended improvement.

Do not present personal style preferences as critical engineering issues.
