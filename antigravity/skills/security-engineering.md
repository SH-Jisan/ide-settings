# Security Engineering

Use this skill when security is relevant to software, applications, APIs, systems, infrastructure, authentication, data handling, or architecture.

## Identify the Security Context

Determine:

* assets that require protection,
* trust boundaries,
* external inputs,
* authentication requirements,
* authorization requirements,
* sensitive data,
* dependencies,
* and realistic threat exposure.

## Apply Secure Design

Prefer:

* secure defaults,
* least privilege,
* defense in depth where justified,
* strong authentication and authorization,
* appropriate input validation,
* secure secret handling,
* safe error handling,
* and dependency awareness.

## Review Realistic Risks

Consider relevant vulnerability classes such as:

* injection,
* broken authentication,
* broken authorization,
* insecure input handling,
* sensitive data exposure,
* insecure configuration,
* dependency vulnerabilities,
* and unsafe trust assumptions.

Prioritize realistic risks based on context.

## Recommend Mitigations

For meaningful risks:

* explain the risk,
* describe realistic impact,
* recommend practical mitigation,
* and explain important trade-offs.

Avoid unnecessary security complexity when the threat does not justify it.

## Verify Security

When appropriate:

* inspect configurations,
* review authentication and authorization flows,
* check input boundaries,
* review dependency exposure,
* and use appropriate defensive testing or analysis.

Clearly distinguish verified findings from assumptions.
