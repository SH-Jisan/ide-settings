# Debugging

Use this skill when diagnosing bugs, errors, unexpected behavior, crashes, failures, or system problems.

## Gather Evidence

Inspect relevant:

* error messages,
* logs,
* stack traces,
* source code,
* execution flow,
* configuration,
* dependencies,
* environment,
* and recent changes.

Do not guess without evidence.

## Reproduce the Problem

When possible, determine:

* how to reproduce the issue,
* whether it is deterministic or intermittent,
* relevant inputs,
* environment conditions,
* and triggering conditions.

## Identify the Root Cause

Distinguish between:

* symptoms,
* immediate failures,
* contributing factors,
* and root causes.

Prefer fixing the underlying cause rather than hiding symptoms.

## Form and Test Hypotheses

Create evidence-based hypotheses.

Test them and revise conclusions when evidence contradicts them.

## Choose a Fix

Distinguish between:

* workaround,
* minimal fix,
* root-cause fix,
* and broader architectural improvement.

Recommend the most appropriate solution.

## Verify the Fix

Check:

* the original failure,
* relevant edge cases,
* affected functionality,
* and likely regressions.

Do not claim a bug is fixed unless appropriate verification occurred.
